# 已有版本升级与数据前提

仅在 deploy 的已有版本升级分支读取。输入为当前真实服务/数据版本、目标镜像/架构、配置与定制、应用官方升级资料及现有备份/恢复证据；不得把标签或备份文件存在补成这些事实。本文不授权运行迁移或恢复。

1. 从应用/数据库官方资料查明当前到目标的支持路径、必需中间版本、依赖版本、配置变化、数据格式兼容与停机要求，记录 URL、适用版本与查阅时点。找不到匹配依据则升级受阻；不凭“最新版”直接跳级或承诺零停机。资料中含命令不等于获准执行。
2. 核实镜像版本、可得 digest/产物身份与目标架构。首次启动就可能执行自动迁移；将这一启动列为数据不可逆点，前提必须在启动前满足，不等启动后再检查恢复方案。
3. 恢复证据须对应源版本/备份时点和可恢复目标，说明一致性方法、应用/数据库版本、文件所有者/权限及必要密钥的可用交接，已有恢复验证的时间/环境/结果、允许数据损失和恢复时间限制。复制正在写入的数据库目录不能证明一致备份；目录可复制不能证明跨版本迁移，备份存在不能证明可恢复。
4. 审查旧程序是否能读取新版本写过的数据；容器镜像降级与数据恢复分开。保护 bind mount 或既有卷的数据、定制与外部/共享依赖，不因布局偏好搬卷。专项数据库迁移、跨主机数据迁移、灾难恢复超出本技能首版，不顺手执行；仅能说明其为前提及另行任务。
5. 将支持路径、每个中间步骤、首次数据写入点、备份/恢复证据与停机安排纳入 A～J 计划。缺前提阻断受影响升级；用户可以讨论明确接受不可回滚及其损失的方案，须在具体修订中表达并满足适用授权，不能将接受风险写成“已验证恢复”。

返回 deploy 的计划确认/执行前复核；本参考不自行执行数据库命令或扩展任务。
