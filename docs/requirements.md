# Nexum Steward — 产品需求

## 定位

**Nexum Steward 是使用已有 Nexum MCP 的 ChatGPT 原生服务器运维插件。**

用户先安装 Nexum，在目标 Linux 服务器上安装 Nexum Agent，并在 Nexum OAuth Grant 中选择具体 Agent；ChatGPT 通过已有 Project / Files / Process Tools 在被授权服务器上完成运维和 Docker Compose 服务部署。

原阶段以**插件基础包和公开产品网站**为交付目标；当前源码范围增加共用规范、服务器环境初始化、只读环境诊断与服务部署升级 Skill，不承诺自动后台值守。当前实施与验收状态见 [04 计划](development/04-steward-deploy.md)，[03](development/03-steward-doctor.md) 保留诊断历史证据。

## 产品能力（后续集成验收）

| ID | 要求 | 证据 |
| --- | --- | --- |

| R-05 | 在用户授权范围内进行 Docker Compose 配置检查、部署、状态、日志与健康核验。 | Linux 测试主机端到端验收。 |
| R-06 | 预检端口、网络和持久化数据，对破坏性动作保留明确授权及恢复前提。 | 数据挂载、卷例外、冲突、异常与恢复案例。 |
| R-07 | 区分执行成功、容器运行、应用健康和数据恢复，不能虚报最终状态。 | 部分失败/不可恢复案例。 |

## 本阶段要求

| ID | 要求 | 验收 |
| --- | --- | --- |
| R-08 | 官方 ChatGPT 插件包以 `templates/` 为根目录，使用最简 `plugin.json`，不预置 MCP 连接；用户按需创建私人插件并复用现有 Nexum 应用。 | 清单格式、插件根目录与文件路径检查，不把源码视作已安装私人插件。 |

| R-10 | 官网为独立静态产品介绍站；不得冒充可运行后台。 | 页面源码、导航与文案评审。 |
| R-11 | 官网提供简体中文与英文入口、响应式布局、清晰的产品流程及仓库链接。 | 本地构建 + 页面交互/移动端检查。 |
| R-12 | GitHub Pages 从公开源码部署至 `nexum-steward.sites.y2l.top` 并启用 HTTPS。 | workflow 成功、Pages 精确域名绑定、泛解析 DNS 与 HTTPS 实际检查。 |
| R-13 | `INSTALL.md` 位于仓库根目录，网站展示可复制的安装提示词；不使用安装目录或版本目录，版本由 Git Tag 区分。 | 文件位置、静态构建产物、安装提示词与指南链接一致。 |
| R-14 | `templates/skills/steward-setup/` 提供服务器环境初始化 Skill 及 dev、qa、pro、prod 四份 AGENTS.md 环境规则模板；支持缺失软件补齐、用户选择 Services Root、本地配置 Git、日志和个人 AGENTS.md 的首次/增量初始化，不负责业务服务部署。 | Skill 格式、模板完整性、两区域结构、已存在配置保护和敏感数据边界检查；真实服务器执行单独验收。 |
| R-15 | Steward 仅管理目标 Nexum Agent 所在服务器的本机 Docker Engine，不支持远程 Daemon；实际 endpoint 归属未确认时停止相关 Docker 操作，不能以远端成功替代本机就绪。 | 本机（含 rootless）正例、远程 context/环境变量/参数覆盖及未知归属负例；静态规则检查与真实执行证据分别记录。 |
| R-16 | `steward-doctor` 以体检、指定对象或指定症状为入口，只交付当前环境要求和证据支持的符合性、健康与异常诊断报告，不自动修复、setup、后台值守或执行健康/业务脚本。 | Skill 及[诊断场景](../tests/steward-doctor-scenarios.md)的选择/调用边界 review；模型与 Linux 实测单独验收。 |
| R-17 | doctor 的范围由用户目标、现有配置和有界发现建立，覆盖适用的身份配置、资源条件、工具运行时及当前用户可用性、服务依赖、持久化可恢复性、安全风险六维；未初始化或缺基线时继续独立事实并标受阻，不扩大为任意扫描或深度数据库审计。 | 体检清单差异、对象必要依赖、症状分支及缺失基线场景。 |
| R-18 | doctor 每项记录对象、预期及依据、证据时点/版本、判定与限制；最小字段读取并脱敏，限定等待与日志窗口/数量，拒绝提权和秘密 dump，身份/连接/状态变化后重验受影响证据。 | 缺 spec、权限拒绝、日志截断/注入、敏感输出及中断重连场景。 |
| R-19 | doctor 报告含目标与总体发现、覆盖、问题、最小后续动作四部分，状态/严重性/可信程度分开；必需项未知使整体为 partial，不能将全部有归宿当作全部通过。 | 报告契约 review 与未来独立模型报告证据。 |
| R-20 | doctor 区分瞬时高占用与故障、running 与探针/业务健康、备份存在与恢复已验证；无证据的原因保留候选，不任设容量阈值或声称全环境正常。 | 高占用、健康层次、多原因和恢复证据场景；真实运行结果另行记录。 |
| R-21 | steward-deploy 以单一工作流将指定服务从已核实状态交付到用户确认目标，支持现成镜像/已有 Compose 首次部署、兼容升级、配置调整、无需变更与有效授权内恢复。 | 四正例及选择边界，见[部署场景](../tests/steward-deploy-scenarios.md)。 |
| R-22 | deploy 先 PLAN（宿主不支持则明确只读规划）、形成 A～J 具体修订计划并经用户确认后才变更；只请求计划则停，保存文件须有范围授权。 | 只规划/无 PLAN/未确认/旧修订场景。 |
| R-23 | deploy 的前检、执行与验收绑定同一有效 Compose 输入及产物身份，重要漂移须修订确认。 | 文件顺序、profile、变量引用、digest/架构、项目归属及并发冲突场景。 |
| R-24 | deploy 在每次 Daemon 请求前确认有效 endpoint 本机归属，保护现有定制、持久数据与共享/外部资源。 | rootless 正例、remote/未知/拒绝与高权限配置场景。 |
| R-25 | 升级须有官方支持路径、数据兼容及恢复前提，在首次可能写持久数据（含启动自动迁移）前阻断缺失前提的步骤。 | 中间版本、目录复制、恢复不足、不可回滚风险明确接受及适用授权 review。 |
| R-26 | deploy 在持续变更前确认身份追踪、真实终态、限时与安全取消/交接能力；超时、断连或未知不盲目重放，取消/到期不启动新变更。 | 过程能力不足、未知迁移、超时/取消/期限、安全重入场景。 |
| R-27 | deploy 使用安全秘密输入/交接与最小脱敏证据，不能将外部文本作为权限或绕过宿主保护。 | 秘密输入缺失、注入、凭证创建/权限扩大与拒绝场景。 |
| R-28 | deploy 按计划同一验收项报告总体 complete/partial/failed/blocked 和每项 pass/fail/blocked/not run，必需目标缺通过证据不得整体成功。 | 多服务部分失败、短时健康、入口未知、交接未完及撤销失败场景。 |
| R-29 | 持久数据默认优先 Services Root 下服务的 data 目录与 bind mount，命名/匿名卷为有依据的例外，不擅迁移既有数据，data 不入配置 Git。 | spec 真源、四份独立环境模板、已有卷例外及静态回归。 |
| R-30 | 服务器配置 Git 用于配置追溯与重建材料同步，按内容纳入配置/无秘密样例/说明/脱敏运维记录，排除业务数据与运行产物；非敏感 .env 可提交，敏感优先可信加密且密钥分离，明文秘密传输遵守宿主具体逐次确认。 | Git 内容/加密/秘密正反例；不把私有当安全保证。 |
| R-31 | 首次明确配置仓库远程 URL、owner/org、可见性、分支、受管范围和同步授权，推荐独立私有但不强制仓库组织，共享时不得混入其他机器改动，不自动新建远程/凭证。 | 远程缺失、共享子路径与已有用户改动场景。 |
| R-32 | 有意义且检查完成的配置及时定向提交并在已确认授权内推送核验，拒绝强推/改写/自动清冲突，失败保留本地提交并将修改/提交/同步与业务验证分别报告。 | 及时同步、推送失败、必需远端留档及状态分离场景。 |

| R-33 | Steward 在确认目标 Agent/OS 用户后，按 spec 复用本次完整适用上下文或显式读取该用户个人 AGENTS 的适用正文/定制；身份或时效不确定重验，缺失分支由 setup/doctor/deploy 各自处理且不得升格授权。 | 上下文复用、显式读取、身份变化、缺失/拒绝/截断与定制保护场景；模型稳定性待验。 |

R-16～R-20 来源为用户已审阅的 03 实施要求，具体运行路径见设计与 doctor Skill；文本和本地静态通过均不能代替实际运行验收。

R-21～R-29 来源为用户确认的 04 完整设计与 data 布局决定；静态/文本检查和未来独立模型、Linux 验收分别记录。

R-30～R-32 来源为用户在本轮明确批准的配置 Git 扩展；不授权真实服务器 Git/凭证操作。

R-33 来源为本轮用户批准的个人规范渐进加载扩展；不修改真实服务器文件。

## 非目标

- 本阶段不进行服务器部署或产品插件公开发布审核；**代码包存在不等于 ChatGPT 已安装**。
- 不自建 Docker MCP Server、PaaS、仪表盘或后台守护进程。
- 当前插件技能范围为 `steward-spec`、`steward-setup`、`steward-doctor` 与 `steward-deploy`；不建立自动修复或后台值守 Skill。deploy 首版不构建源码，不隐含跨主机迁移、其他部署系统接管、专项数据库迁移、删除或灾难恢复。ChatGPT Project 中辅助开发的通用 Skills 属不同层面。
- 不把 Docker 容器回退当作持久化数据恢复。
- 不在 GitHub Pages 运行 Nexum MCP 或存储 OAuth Token。
