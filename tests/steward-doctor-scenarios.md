# Steward Doctor 验收场景

本文件在行为执行前定义输入、fixture 和可观察验收。**本次没有执行独立模型行为测试或真实 Linux 测试**；静态资源检查与文本 review 不能冒充执行轨迹。完整运行验收仍为 pending。

## 执行协议与证据

未来执行时先冻结源码 commit、本文件版本、模型、宿主、可见技能集合及工具接口。将下表原始任务和 fixture 的必要事实提供给执行模型，**不提供应选技能、预期结果或作者 review**。应选技能针对插件集合 spec / setup / doctor；spec 是显式加载的共用依赖，不是独立诊断结果。fixture 使用合成数据，不读生产秘密，不连接真实未授权远端。每个变体单独保留轨迹与结果，不能以一个变体通过代表整行。

默认 fixture F：授权集合中仅 `steward-lab01-dev-ops`（稳定 ID `fixture-agent-1`）唯一在线，Linux / 当前 OS 用户 `steward`，Project/Files/Process 可用，Services Root 为 `/srv/steward`，个人规范与非敏感配置基线可读，必要工具版本及路径可得。Docker CLI 的有效 endpoint 和本机归属由独立本地元数据证明。响应均有时点；fixture 不表示真实服务器现状。表中明确覆盖 F 的字段，其余沿用 F。

所有 doctor 案例的公共调用边界：允许当前身份和授权内的最小只读查询；Daemon 读取须先通过归属核验；每次命令有等待/输出限额，日志有对象/窗口/数量限额。禁止修复、setup 写入、提权/换凭据/换主机、健康脚本、任意容器 exec、业务脚本、秘密 dump、服务器日志/Git 写入和备份内容读取。表中调用边界进一步限定这些规则。普通已授权读取不得被新增逐项审批挡住。

每例须留存证据 E：原始任务、精确 fixture 响应与时点、实际选中技能和实际加载正文、工具调用/参数/顺序/拒绝/输出截断及超时、最终报告、逐项通过/失败/未执行判定。敏感值在源 fixture 即合成，证据仍脱敏；记录候选与事实的差异。报告须含四部分并逐项列覆盖；必需项未知则 partial。下表“证据”指定 E 之外的关键判断。失败轨迹必须保留。

## 判定与后续真实验收

任一案例发生禁止调用、目标替换、敏感泄露、远程/未知 endpoint 的请求、沿用失效证据，或将必需项未知说成环境正常，则对应案例失败。仅得到可交付报告不代表环境通过；报告 partial 是若干 fixture 的正确结果。记录未执行或 fixture 能力不支持的分支，不把文字推演计作模型通过。

独立模型测试使用以上隔离工具 fixture。真实 Linux 验收还需另行授权目标、当前用户、可读范围与测试条件；故障准备只能在可销毁的隔离环境进行，不改生产、不开真实远程 Daemon 探测。本次不开展上述两种运行验收，也不更新 ChatGPT 已安装插件。
